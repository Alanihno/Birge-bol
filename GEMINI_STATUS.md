# Gemini — подключение проверено

Ключ предоставлен владельцем и сохранён зашифрованным в Supabase Vault под именем `birge_bol_gemini_api_key`. Значение не находится в исходниках, .env, статической сборке или архиве демо. Клиентские роли anon/authenticated не могут читать секрет или вызывать служебный getter. Edge Function получает его только серверным service_role.

Активна модель gemini-2.5-flash. Ограничения: 10 запросов в час на пользователя и 20 запросов в сутки UTC на весь проект, максимум 350 выходных токенов, таймаут провайдера 8 секунд. Глобальное отключение: `update private.ai_settings set enabled=false where singleton;` из доверенного SQL Editor. Также `AI_ENABLED=false` в Edge secrets отключает вызовы. Квота не означает гарантированной бесплатности API.

Проверено 11.11.2026:
- Google models API: HTTP 200; минимальный generateContent: HTTP 200, ответ OK.
- Полный серверный flow через настоящую сессию временного синтетического Auth-пользователя: Auth 200, Edge Function 200, provider=gemini, объяснение из 188 символов, без fallback. Тестовый аккаунт/сессии удалены; письмо никому не отправлялось.
- SQL-проверка: anon и authenticated не получают ключ, service_role получает конфигурацию; второй вызов при тестовом дневном лимите 1 отклонён. Тест откатан, рабочий лимит 20 сохранён.
- Security advisors после настройки: lints: [].
- Frontend build, TypeScript и lint прошли.

В подключённой версии `/explain` после входа есть «Объяснить проще с Gemini». Отправляется только выбранный термин из словаря. Введённый свободный фрагмент, профиль ребёнка и документы не передаются. Исходное объяснение остаётся доступным, сбои/квоты не блокируют словарь.

Папка «деплой версель» остаётся автономным демо без внешнего ИИ и ключей. Подключённая версия собирается обычной командой `npm run build`; production origin нужно добавить в ALLOWED_ORIGINS, Auth Site URL и Redirect URLs после появления фактического домена. Доступ по email и юридические условия реального сервиса — отдельный этап.

Для другого проекта примените миграцию `birge_bol_gemini_vault`, задайте секрет с указанным именем через Vault UI и включите private.ai_settings доверенным SQL. Сам ключ в миграцию не вставляйте. Исходники функции находятся в `supabase/functions/explain` и `_shared/gemini.ts`.
