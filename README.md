# Birge Bol

Актуальное обновление Promt3: кабинет специалиста `/pro` по предоставленному HTML, три роли и связанный сценарий записи/отзывов/заданий. Результат, проверки и внешние настройки — [PROMT3_STATUS.md](PROMT3_STATUS.md); сценарий — [DEMO_SCENARIO_PROMT3.md](DEMO_SCENARIO_PROMT3.md).

Готовая автономная папка для Vercel Drop: **«деплой версель»**. Сборка без ключей: `npm run package:demo`. Загрузка — DEPLOY_DEMO.md; ограничения и ключи — DEMO_STATUS.md и DEMO_KEYS.md. `npm run build` сохраняет обычную конфигурируемую версию, `npm run build:demo` создаёт изолированную демонстрацию в dist-demo.

Учебный MVP PWA для семей в Казахстане: «Найти. Понять. Видеть прогресс». React + Vite + TypeScript; без Next.js, постоянного сервера и обязательных платных API.

## Быстрый запуск

Нужен Node.js 22.18+ или 24, npm.

```sh
npm install
cp .env.example .env.local
npm run dev
```

Windows PowerShell: используйте `npm.cmd`, если политика системы блокирует `npm.ps1`; скопируйте `.env.example` через `Copy-Item`. В переданном рабочем каталоге `.env.local` уже настроен на предоставленный Supabase-проект; файл исключён из Git. Не заменяйте его шаблоном, если хотите сохранить подключение.

Для полностью локального демо задайте `VITE_APP_MODE=demo`. Откройте `/find?mode=demo` или переключите режим в настройках. Явное переключение сохраняется в sessionStorage вкладки. Без ключей демо работает; для личных действий есть кнопка «Войти в демоаккаунт». В production режим нужно задать явно. Если выбран Supabase без конфигурации, приложение показывает ошибку настройки и не подставляет демоданные.

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run preview
npm run test:e2e
```

Проверки браузера используют установленный Chrome на Windows. На другой ОС задайте `CHROME_PATH` либо установите Playwright Chromium и уберите локальный путь в конфигурации. `BASE_URL` позволяет проверять готовый preview. Актуальные выполненные проверки — в `VERIFICATION.md`.

## Что работает

Анкета без входа с локальным черновиком → правила с объяснением → поиск/фильтры/сортировка и карта → профиль специалиста → избранное/ручная отметка занятия → вопрос с предпросмотром и частичным удалением идентификаторов → чек-лист и редактируемый отзыв → цели, наблюдения и два нейтральных аудиопримера → словарь. Есть профили нескольких детей, настройки, уведомления, privacy/terms, 404, защищённая модерация.

24 вымышленных специалиста Астаны, 25 учебных терминов и синтетические вопросы. Нет реальных контактов, подтверждённых отзывов или свободных слотов. Координаты не придуманы: карта показывает обзор города без отметок. «Стаж» и цены в примере вымышлены. Правила — версия `2026.11.demo.1`, требуют профессиональной проверки. Оценка контакта отделена от медицинского результата; при малой выборке рейтинг скрывается.

В демо данные синтетические и находятся в браузере. В Supabase адаптер обращается к реальному API с RLS; ошибки не заменяются локальными данными. Публичный каталог проекта тоже помечен как синтетический. Начальный Алихан и готовая цель существуют только в локальном демо; серверные дети не создаются автоматически.

Основная навигация и главный экран имеют русский/казахский словарь. Полный перевод остальных форм и учебных материалов пока не завершён; статус указан в настройках.

## Supabase

В этом рабочем каталоге настроен проект `sychksvkgwrgyhxpaabt`. Публичный anon key находится только в игнорируемом `.env.local`. Это публичный клиентский ключ; он попадёт в frontend build по назначению. Секреты service_role, Gemini и Telegram в frontend отсутствуют.

Для другого проекта создайте проект Supabase, заполните URL/anon в `.env.local`, примените миграции из `supabase/migrations` по порядку и затем `supabase/seed.sql`. Seed содержит только синтетические публичные примеры. Повторное применение seed не заменяет существующие записи; для разработки используйте отдельный проект. SQL-тесты находятся в `supabase/tests/rls.sql` и полностью откатываются.

Установите Supabase CLI по [официальной инструкции](https://supabase.com/docs/guides/local-development/cli/getting-started), проверьте `supabase --help`, затем:

```sh
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase db push
supabase db query --linked --file supabase/seed.sql
```

Наличие команды `db query` зависит от версии CLI; SQL Editor поддерживает те же SQL-файлы. В существующем проекте миграции уже применены через MCP — не запускайте их повторно вручную.

Auth → URL Configuration: Site URL = фактический production URL. Разрешите точные redirect URLs `http://localhost:5173/auth`, `http://127.0.0.1:5173/auth`, `https://YOUR_DOMAIN/auth` (и разрешённые preview URLs). Приложение использует email magic link, восстановление сессии и logout. Для реального email-пилота настройте доставку/SMTP и лимиты Auth; фактическая доставка на чей-либо email в этой работе не проверяется. До назначения оператора не запускайте публичную регистрацию реальных семей.

Роли создаются только доверенным SQL-администратором:

```sql
insert into public.user_roles(user_id,role)
values ('EXISTING_AUTH_USER_UUID','admin')
on conflict(user_id) do update set role=excluded.role;
```

Никогда не используйте user_metadata для авторизации. `/admin` проверяет роль; БД независимо применяет RLS. Админ не получает права читать приватные профили детей. Отзывы проверяются по статусу и evidence; синтетические отзывы нельзя пометить настоящими подтверждёнными посещениями. Текущий UI поддерживает проверку очереди/отклонение, CRUD профиля и скрытие публикации; полный evidence workflow и управление наставницами — следующий этап.

SQL сбрасывает широкие default grants Supabase, создаёт owner-политики и составные FK для межсемейных ссылок. `submit_feedback` атомарно сохраняет ответы и отзыв. `save_synthetic_child` сохраняет вымышленный профиль и запись согласия. Публичных bucket для детских медиа нет. Сгенерированные типы: `src/lib/database.types.ts`.

## Edge Functions

**Gemini подключён к текущему серверному проекту и проверен.** Ключ зашифрован в Vault, а не в frontend. Текущие настройки, лимиты и результаты — в GEMINI_STATUS.md. Для изолированного Vercel Drop демо ИИ отключён намеренно.

Исходники: `supabase/functions`. `explain`, `account-delete`, `telegram` требуют JWT и проверяют пользователя. `telegram-webhook` проверяет webhook secret и по умолчанию возвращает `integration_disabled`. Ограничение объяснений: 10 запросов/час на пользователя в БД; вход до 2 KB, таймаут провайдера 8 с, fallback на словарь. Логи не содержат приватный текст.

```sh
supabase functions deploy explain
supabase functions deploy account-delete
supabase functions deploy telegram
supabase functions deploy telegram-webhook --no-verify-jwt
supabase secrets set ALLOWED_ORIGINS=https://YOUR_DOMAIN,http://localhost:5173
```

`account-delete` сначала отзывает сессии, затем удаляет Auth-пользователя и данные по FK. Доступ возможен только владельцу. Уже выданные JWT не становятся мгновенно недействительными: после удаления владелец отсутствует, приватные строки удалены; строгие гарантии отзыва всех токенов и сроки backup retention требуют отдельного аудита.

Gemini необязателен. Для другого проекта примените миграции, создайте секрет `birge_bol_gemini_api_key` в Vault UI и включите `private.ai_settings` доверенным SQL. Модель проверяйте по [актуальному каталогу Google](https://ai.google.dev/gemini-api/docs/models). Функция принимает только название из словаря, а не исходное заключение или детские данные. В серверном интерфейсе после входа доступна отдельная кнопка упрощения; локальный словарь работает независимо. API: `supabase.functions.invoke('explain', {body:{term:'ЗРР'}})`. Лимиты: 10/hour на пользователя и 20/day на проект. `AI_ENABLED=false` отключает провайдера. Gemini не участвует в клинических решениях и не обещает безлимитную бесплатность.

Telegram: in-app демо полностью работает. Настоящая отправка, безопасная привязка наставниц, opt-in delivery mapping и приём ответов НЕ включены. Даже при добавлении токенов webhook закрыт до реализации linking. Заглушки не имитируют доставку. Не регистрируйте production webhook до завершения этого этапа.

## Vercel

Импортируйте репозиторий на Vercel: Framework Preset **Vite**, Build Command **npm run build**, Output Directory **dist**, Node 22/24. Постоянный Node-сервер не нужен.

Публичные переменные frontend: `VITE_APP_MODE` (`demo` или `supabase`), `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. Пересоберите после изменений. Секреты Gemini/Telegram/service_role задавайте только в Supabase. Настройте Auth Redirect URLs и серверный ALLOWED_ORIGINS на фактический домен. Для preview используйте отдельный Supabase-проект/разрешённые origin, без реальных данных.

`vercel.json` содержит SPA fallback; статические иконки, аудио, manifest и SW обслуживаются как файлы. Обновление service worker требует подтверждения в настройках. Кэшируется только сборочная статика, нет runtime cache авторизованных API. Offline не означает доступность серверных записей без сети.

Smoke после деплоя: открыть `/find`, обновить `/specialists/00000000-0000-4000-8000-000000000001`, проверить `/manifest.webmanifest`, `/sw.js`, `/icons/icon-192.png`; пройти учебный сценарий и проверить офлайн-оболочку. Нельзя заявлять production-ready privacy или performance score без аудита и измерений.

Vercel подключённый аккаунт в этой сессии вернул 403 на доступ к команде. Развёртывание сайта не подтверждено; исходники и static build предназначены для самостоятельного импорта. Никакой production URL не выдумывается.

## Границы MVP

Нет настоящего бронирования, автоматического листа ожидания, push/cron-напоминаний, OCR, загрузки документов или детского голоса, клинической диагностики и кабинета специалиста. Полный Telegram, механизм реальной верификации посещений, редактирование версий правил с публикацией из БД и полный казахский перевод — roadmap.

Перед реальными персональными данными обязательны независимая правовая проверка Казахстана, выбор размещения, privacy/security audit и профессиональная проверка словаря/правил. См. `SECURITY_AND_COMPLIANCE.md`. Наличие галочки согласия не решает эти вопросы. У бесплатных тарифов есть лимиты и условия; выбор коммерческого Vercel тарифа и бюджет внешних API проверяются отдельно.

Оригинальные SVG/CSS-иллюстрации и PNG-иконки, нейтральные синтезированные WAV созданы в проекте. Inter — [SIL OFL](https://github.com/rsms/inter), Lucide — ISC. Фотографии людей не используются. OSM attribution сохранена; при росте нагрузки нужен подходящий tile provider по его правилам.
